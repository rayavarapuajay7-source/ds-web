01 / INSTALL

Start the server.

Run Kestrel locally with Docker. The default port is 6380; data is held in memory and is cleared when the process exits.

TERMINAL
docker run --rm -p 6380:6380 ghcr.io/kestrel-kv/kestrel:latest

Note: This example is for local development. Configure access controls and memory limits before exposing an instance to a network.

02 / CONNECT

Use a familiar client.

Kestrel speaks a Redis-compatible protocol. Pick a language to see a tiny connection example.

JAVASCRIPT
import { createClient } from 'redis';

const client = createClient({ url: 'redis://localhost:6380' });
await client.connect();

await client.set('greeting', 'hello, kestrel');
console.log(await client.get('greeting'));

03 / COMMANDS

A small, useful core.

GET keyRead a string value.
SET key valueWrite or replace a value.
DEL keyRemove a key.
EXPIRE key secondsSet a key's time to live.
TTL keyInspect remaining lifetime.

04 / OPERATE

Know your limits.

In-memory storage requires an explicit memory budget. Track resident memory alongside request latency, set a container limit, and leave headroom for the process and client buffers.

Not a durable database.Kestrel stores data in memory. Treat the process as ephemeral unless you have configured and verified a separate persistence strategy.

05 / MEASURE

Test your workload.

Run benchmarks from a separate client process and use the same machine, network path, value size, and concurrency as your application. Always compare tail latency as well as throughput.
